# ADR 0017: 事件流写者约定细化——同进程多实例串行化写入

- 状态：Accepted
- 日期：2026-08-27
- 对应 issue：#120（实战反馈整体计划 v2，Wave 1a）+ 独立复核必改 1
- 实施分支：`feat/wave1a-agent-tools-attach`（PR #122）
- 评审留痕：#120 v2 计划评论 + 合并前独立子 agent 对抗性评审结论

## 背景

docs/agent-team/11-generic-runtime.md §5 冻结约定「事件流仅运行时单写者」：
同一房间同一时刻只允许一个运行时实例写 `events.jsonl`，多进程并发写同 room
属协议违规。

Wave 1a（PR #122）把工具面 handler 绑定改为与 HTTP 视图路由同款反查后，
**主控与其子代理共享同一 TEAM_HOME 实例根**——子代理经工具面触发的写副作用
（`team_task_update` 等 handler 内 `appendEvent`）与主控写的是**同一
events.jsonl**。此时「单写者」若按字面解释为「单 EventLog 实例」，主控与
子代理各自 `createHandlers` 得到的独立 EventLog 实例并发 append 会产生
seq 重复/乱序（per-instance `nextSeq++` + `flag:"a"` 追加）。

本 ADR 记录这一语义细化：**单写者约定从「单实例」放宽为「同进程多实例
串行化」，跨进程边界不变**。编号采用 0017（顺延的下一个编号已被 #97
lastSeen 计划预占，避免并行撞号）。

## 决策

### 1. 事件流写者约定（修订 11§5 语义）

| 维度 | 原约定（11§5） | Wave 1a 细化后 |
|---|---|---|
| 同进程内 | 单写者（单运行时实例） | **多实例（主控/子代理 handler 集）可并发 append，由 per-file 进程内写队列串行化** |
| 跨进程 | 不做仲裁（room.lock 承担） | 不变：仍属协议违规，本层不仲裁 |
| seq 分配 | per-instance 游标 | **模块级共享游标**（以事件文件绝对路径为键），只在写队列任务内读写 |

### 2. 实现要点（event-log.ts）

- `EventLog.append` 整体入队：以 `events.jsonl` 绝对路径为键的 Promise 链
  （`enqueueAppend`），串行化「读共享游标 → 构造记录 → 写文件 → 推进游标」；
- `init()` 扫描恢复游标时取「文件现状与既有共享游标的较大者」——多实例
  并发 init 不失序、不回退；
- 游标推进在 `writeFile` **成功之后**：写失败不推进，后继 append 复用同
  seq，与 torn-tail「坏行不计入游标、重写同 seq」语义一致，消除失败空洞；
- 前一任务失败不阻断后继（`prev.catch(() => undefined).then(task)`）；
- 进程内共享游标/写队列是**模块级**状态：进程重启后 `init()` 重扫恢复，
  跨进程 seq 不在此收敛（与 DSH_HOME 运行期变更同理，不在支持范围）。

### 3. 不改变的部分

- 「无 agent 写路径」边界不变：事件流仍是框架层（handler）写入，agent 不
  直接写文件；
- 跨进程多写者仍属协议违规，仲裁责任仍归 room.lock（cas-lock）。

## 备选与裁决

- **备选 A：工具面继续直查各会话自己的 TEAM_HOME（不共享）**——否决：
  Wave 1a 目标就是打通子代理 → 主控实例，回退即退回 #86 问题 4。
- **备选 B：跨进程/跨实例互斥锁（文件锁）**——否决：主控与子代理是
  **同一进程内**的多个 handler 集，文件锁是为跨进程设计，同进程内会退化为
  自旋/加锁开销；且事件 append 频率低（每次工具调用 1-2 条），Promise 链
  开销可忽略。
- **备选 C：事件流改为每成员独立文件**——否决：破坏「房间 = 事件流」的
  既有模型（11 文档 §5 房间目录组织），对账/回放口径全部要改，收益不抵成本。

## 后果

- 正面：主控/子代理共享事件流后 seq 单调不重复，事件回放、reconcile 游标、
  对账口径全部一致；并发护栏有独立单测覆盖（两实例并发 append 10 次
  seq 1..10 唯一；失败不推进游标）。
- 负面/风险：模块级共享游标在「进程运行期事件文件被外部替换/重建」场景
  不与文件同步（只增不减）——已声明为不支持场景（与 DSH_HOME 运行期变更
  同理）；跨进程并发写仍需 room.lock 或协议纪律约束，本 ADR 不承诺收敛。
- 兼容性：EventLog 公共 API（`init/append/read/count`）签名不变；`append`
  由 async 改为返回 Promise（调用方均 await，无破坏）；`WRITER_LOCK_SUFFIX`
  保留导出（兼容既有引用）。
- 流程：本 ADR 为 Wave 1a 已合入实现的补记留痕；docs/agent-team/ 为冻结版
  定稿，正文不改，语义修订以本 ADR 为权威增量。
