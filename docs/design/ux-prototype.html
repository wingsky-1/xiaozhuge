设计对照

体验稿与 UI/UX 演进方案（U0–U3）的逐条对应。本稿是设计提案，不是实现；一切落地以对应 issue 评审为准。

PRINCIPLES · 五条设计立场

原则 → 稿中体现

  • 单入口 · 两触点零门槛：待办页打开即见（U0-b）；对话流·去裁决 链接演示不离开对话的裁决动线。
  • 展示即账本：每张卡附事件证据链，状态变化同步追加 gate/resolve seq；抽屉与尾窗全是账本投影。
  • 数据面走官方通道：对话节点是「协作事件入会话日志 → 投影」的愿景形态（U2-a/b 先 spike）。
  • 自建只留官方没有的：树形组织/房间/注册表自建；列表、表单、徽标皆素材化，不造组件轮子。
  • 最小适配税：素稿无外部依赖、双主题、375px 一等适配；实现面维持官方插槽形态。
STAGES · 阶段对应

U0–U3 → 稿中区域

  • U0-a gate 强制语义：卡的「绑定」行与证据链是视觉提案；执行器/自动开闸/灰度以 #53 评审为准，不在本稿承诺内。
  • U0-b Console 零门槛：待办·打开即见 最近活跃实例默认展开、其他实例显式展开、375px 预览。
  • U0-c 入口露出：团队·待办 2 入口按钮（shell.overlay 徽标待 U2-a 投影落地后再评）。
  • U0-d 规程小修：提示词侧，无视觉面（Tier-0 发现待裁门写原生 todo）。
  • U1 还债：团队·尾窗、事件白名单摘要、task/update 带 title、无上限任务不显示 n/m（T-105 未入稿即示例）。
  • U2 数据面官方化：对话流 整页为 U2-a/b spike 通过后的目标形态。
  • U3 纵深：未入稿（依赖 U2 投影）。
NOT-DO · 不做清单

明确不做

  • 迁官方 approval 承载 Gate——实证语义错位：单 agent 实时瀑布、离线即 abort、fail-closed、决策域两值，无持久待办。
  • 用官方 Trajectory 回放协作事件——消费模型会话专属语义（token/TTFT），且无自定义事件源接口。
  • 建团向导 G2——触发条件重估中，不借 UI 重启。
  • 视觉重做——问题在人机回路断裂，不在观感；本稿只演示回路修复后的形态。
  • 新增 REST 轮询面——新数据面一律投影通道，存量 REST 冻结并设移除里程碑。
SIGNATURE · 签名时刻

一次裁决，三面同步

  • 在待办页对 plan-approval 点「批准」：朱批落卡，证据链入账 gate/resolve。
  • 切到团队：T-104 已解锁 running，coder 转青瓷，游标推进。
  • 切到对话流：gate 节点翻转为「已裁决」，军师接话继续派发。
  • 驳回则全程走驳回语义（玄墨「驳」印、任务转 cancelled）。
  • 试完点右上「重置演示」复原。
